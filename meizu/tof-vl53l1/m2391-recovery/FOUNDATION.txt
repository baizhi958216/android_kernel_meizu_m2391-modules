M2391 OEM integration recovered from original ELF
-----------------------------------------------
The OEM calibration commands are c1a87015 (save) and c1a87016 (load).
Their userspace packet is 424 bytes: is_read at0, 408 opaque ST bytes at4,
UID at416. Persistent slot265 stores416 bytes: calibration at0 and raw UID
at408. Save reads current sensor UID (NVM words126..127) with delays allowed,
then current calibration; it does not trust userspace calibration or return
a packet. Load returns the slot record and does not program hardware.
Original successful-command storage-error handling is retained and logged.
Source static assertions protect all these sizes/offsets. Evidence is the
annotated stock-oem-ioctl.disasm and stock-slot.disasm.

Restored OEM IPC logging, including dual IPC/console errors; tof_rgltr supply
name, named-GPIO phandle resolution, Meizu dtof input-device link, and the
s_module_load_state zero => EPROBE_DEFER dependency. OF compatibles are not
expanded: original AI table dtof,ai11ba_i2c does not match local DTS's
adaps,ai11ba_i2c, so this existing board-description mismatch remains explicit.
Both original and source ST OF table use st,stmvl53l1. No alternative chip
or register sequence was substituted.

Safety corrections to the licensed foundation: initialize kref before misc
publication; publish controls only after device initialization; mark removed
under the operation mutex before draining sysfs/misc/work without that mutex;
open descriptors retain object references and reject hardware access after
removal. IRQ/poll callbacks reject removed devices. Fix allocation check,
input-allocation failure free, dev-ID allocation reservation, supply unwind,
and drain polling work on failed setup as well as remove. Hardware/IRQ/GPIO
resources are released before dropping the owner reference. Millisecond tick
API now returns a real monotonic timestamp rather than the original trap.

Full actual composite vl53l1.o Kbuild passed with the OEM command and lifecycle
