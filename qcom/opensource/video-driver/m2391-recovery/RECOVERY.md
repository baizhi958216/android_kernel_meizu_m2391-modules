# M2391 video source recovery

The licensed Qualcomm foundation covers the original Kalama/Crow, Iris2/Iris3 DT variants and the original V4L2/HFI userspace protocol. Initial stock/source comparison found 814 exact functions/data objects; all original hardware/platform tables match after recovery, apart from compiler CFI alias spelling. The stock-only Video-Banner is build provenance (the old Flyme builder/date is not fabricated in a new source build).

Recovered stock policies include Kalama MAX_RT_MBPF=174080 and VBV 200..300/step100/default300; original GOP/layer dependencies; no added VBV34..100 force-layer, stage or pipe policy; original nominal-frequency limit and session counting. Original overload handling records a pending decoder priority change, then applies it once in decoder qbuf. The foundation's immediate database update was removed so it cannot be applied twice. Original FW_TRACE diagnostic availability is retained. Decoder batch delayed-work initialization had moved from decoder init to common open; it was present, not a missing OEM feature. The licensed FIRST_IPSC split-mode first-PSC buffer-reuse correction is retained as an internal foundation fix with unchanged wire controls.

Actual complete `msm_video.o` Kbuild passed against prepared M2391 Kalama/Crow core headers, LLVM LTO and CFI. Standard linker-script processing of actual `.o.symversions` reproduces all 33 original export CRCs, classes and namespaces. A direct retained-ELF undefined-symbol scan found no stock consumer of these exports. No snapshot CRC is injected into source output.

Removal now withdraws V4L2 publication, wakes blocked DQEVENT, stops work admission and drains SRCU operations before closing sessions while HFI/IOMMU remain valid. Successfully pinned instances become tombstones; a descriptor close drops its owner immediately, without waiting for userspace close or competing for teardown's media-request mutex. The removing thread owns a separate pin until real resource cleanup completes. Zero-reference instances are never resurrected or assigned nonexistent pins. In-flight opens are caught by a second scan after the first SRCU drain. Poll uses a retained instance waitqueue bridged to all five original event/buffer waitqueues, preserving ordinary event delivery while avoiding references into freed vb2 queues.

IRQ registration uses NO_AUTOEN. Every work producer is gated by the async lock; core and instance work is canceled before resources are destroyed. Session-close responses finish under synchronize_irq before instance resources are released. The threaded IRQ's final enable and IRQ withdrawal share core->lock; free_irq drains outside that mutex. IRQs are removed before capability/DT storage is freed. Instance debugfs drains before its backing data is released, and all instance roots are removed before their parent root.

Video devices retain the core's pure embedded state until their final release. Media devnodes and independent request descriptors also retain that state; each request retains the driver module, and core state retains the parent device. Media cleanup is deferred until the final reference so old V4L2 release and request ioctls still have a valid request mutex. Request allocation, validation and queueing reject a stopped core; teardown holds the original req_queue_mutex while releasing vb2/request objects. This does not keep hardware or IOMMU resources alive until arbitrary descriptors close.

Native media fixes pair existing unregister wakeups with a disconnected-device DQEVENT condition. Media ioctl SRCU protects registered-check through handler completion; unregister withdraws registration under graph_mutex, drops graph/req locks while draining admitted ioctls, then removes graph state. A separate unregister mutex preserves completion serialization of concurrent unregister calls. Registration failure after node publication drains ioctls too. All native media-controller C objects and v4l2-event.o passed real prepared Kbuild.

Child context-bank removal first performs the same terminal session stop, then clears its fault-handler entry and removes its devm node from the core list. Rebind of a stopped parent is rejected. The fault callback compares ready/global-core identity before dereferencing its opaque cookie. Clearing iommu_set_fault_handler alone does not drain callbacks: this board has no VFIO/external domain holder, and parent depopulation releases the default domain; arm_smmu_destroy_domain_context synchronizes its IRQ before core/module release. The old cookie remains valid until that drain. The singleton is cleared only after all child domains are removed, preventing rebind ABA. PM and module-parameter callbacks also use the admission gate.

Parent independently reviewed native media cancellation/SRCU, request/core/node references and removal locking. Hardware execution was not performed; full local ROM integration build remains a final step.
